# The resolved tree behind requirements.txt, so a build is the same artifact on any day and on any
# runner. Without it the direct tools are pinned and everything they pull in floats to whatever PyPI
# serves at build time: the same commit produced msgpack 1.2.1 on one machine and 1.1.2 on a CI
# runner, which is how a gate goes green locally and red in CI.
#
# The direct tools are not repeated here. They are in requirements.txt, which is what the Dockerfile
# installs with -r, and this file is applied with -c.
#
# A constraint is not an install. Nothing here is added to an image that would not have pulled it
# anyway, so setuptools stays absent from every target and is pinned only as a floor, in case a source
# build ever drags it in.
#
# Regenerate against the pinned base after any version in requirements.txt moves:
#
#   docker run --rm python:3.14.7-alpine3.24 sh -c '
#       apk add --no-cache build-base libffi-dev openssl-dev linux-headers > /dev/null
#       python3 -m pip install --no-cache-dir --quiet "pip==<V>" "poetry==<V>" "debugpy==<V>"
#       python3 -m pip freeze --all'
#
